# ADR 0002. Database-per-service (PostgreSQL)

- **Статус:** Accepted
- **Дата:** 2026-04-10

## Контекст

При микросервисной архитектуре сервисы не должны разделять схему хранения:
это создаёт связанность на уровне БД. Требуется изоляция данных.

## Решение

- Каждый сервис с реляционными данными имеет **свою базу PostgreSQL**:
  `ecotech_catalog`, `ecotech_identity`, `ecotech_order`.
- Сервис **не читает** чужие БД: обмен — только через API/события.
- Basket хранит состояние в **Redis** (не реляционные данные).
- Search хранит индекс в **Elasticsearch**.
- Доступ к данным — через **EF Core** (Npgsql) + миграции.

## Последствия

- (+) Полная изоляция, независимые миграции и масштабирование.
- (+) Чистая модель владения данными.
- (−) Денормализация и синхронизация через события (eventual consistency).
- (−) В dev поднимается несколько контейнеров PostgreSQL (см. docker-compose).
