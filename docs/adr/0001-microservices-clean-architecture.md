# ADR 0001. Микросервисы + Clean Architecture

- **Статус:** Accepted
- **Дата:** 2026-04-10

## Контекст

Проект учебный, но должен быть уровня enterprise и разворачиваться на сервере.
Нужно задействовать как можно больше современных систем (брокер, кэш, БД-на-сервис,
наблюдаемость), т.е. микросервисная архитектура с разделением по домену.

## Решение

- Разбить систему по бизнес-возможностям (bounded contexts): Identity, Catalog,
  Basket, Order, Notification, Search + ApiGateway.
- Внутри каждого сервиса — **Clean Architecture** (Domain → Application →
  Infrastructure → Api), связи через интерфейсы, зависимости внутрь.
- Использовать **DDD** (агрегаты, value objects, доменные события) и **CQRS**
  (MediatR) в Application-слое.
- Общие технические вещи — в `BuildingBlocks` (Core, Messaging, Observability, Web).

## Последствия

- (+) Слабая связанность, независимый деплой и масштабирование, соответствие теме.
- (+) Единый стиль кода во всех сервисах, удобно тестировать.
- (−) Больше кода и инфраструктуры, чем у монолита (осознанно, ради обучения).
- (−) Нужны контракты и идемпотентность при межсервисном взаимодействии.
