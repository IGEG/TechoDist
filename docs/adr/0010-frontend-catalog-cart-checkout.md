# ADR 0010. Фронтенд витрины и админки: серверная корзина, TanStack Query и продление токена

- **Статус:** Accepted
- **Дата:** 2026-10-04

## Контекст

К фазе 8 SPA должен закрыть весь покупательский путь (каталог → корзина → заявка → статус)
и админ-CRUD каталога. При этом открыты три вопроса:

1. Где живёт состояние корзины, если покупатель не аутентифицируется (ADR 0005)?
2. Как связать серверные данные, мутации и UI, чтобы после правки в админке витрина не показывала
   устаревшие карточки?
3. Что делать с 15-минутным access-токеном админ-панели (ADR 0004), чтобы сотрудник не вылетал
   на форму входа посреди работы?

## Решение

**1. Источник истины — сервер.** Корзина и заявка живут в Basket/Order, а не в браузере: снимок
названия и цены приходит из Basket (ADR 0005), заявка создаётся из серверной корзины по
HttpOnly-cookie. Страница корзины и бейдж в шапке — только представление одного и того же
ответа `GET /basket/api/basket`; своего дублирующего состояния в store нет.

**2. Кэш — TanStack Query, ключи выводятся из параметров.** Список товаров кэшируется по
`['catalog','products',params]`, корзина — по `['basket','current']`, админский список — по
`['admin','catalog','products',params]`. Мутации корзины возвращают свежий `BasketDto`, поэтому
пишут его в кэш через `setQueryData` — бейдж, страница корзины и оформление обновляются без
повторного GET. Правки каталога инвалидируют **и** админский, **и** витринный ключи: кэш Redis
сбрасывает сервис, кэш TanStack Query — фронтенд.

**3. Токен продлевается заранее.** HTTP-клиент получает токен через асинхронный хук
`getAccessToken` (Axios дожидается интерсептора). Если `expiresAt` ближе 60 секунд и есть
refresh-токен, store один раз (single-flight, `refreshInFlight`) вызывает token-endpoint с
`grant_type=refresh_token` и заменяет сессию. Отклонённый refresh сбрасывает сессию — guard
уводит на `/admin/login`.

## Последствия

- (+) Один кэш и один HTTP-клиент на витрину и админку: состояние не дублируется между store и
  сервером, а инвалидация описана в одном месте (`use-admin-catalog.ts`).
- (+) Продление токена незаметно для пользователя: запрос уходит уже с новым access-токеном,
  повторный логин нужен только при отзыве refresh-токена.
- (+) Публичные страницы грузятся сразу, админ-разделы — ленивыми чанками, поэтому бандл витрины
  не растёт вместе с админкой.
- (−) Правила инвалидации нужно соблюдать при добавлении новых мутаций, иначе часть экранов
  покажет устаревшие данные.
- (−) Фронтенд знает структуру DTO каждого сервиса (`src/lib/api/types.ts`): контракт меняется —
  правится и SPA (типы дублируются осознанно, кодогенерация из OpenAPI — за рамками фазы).
