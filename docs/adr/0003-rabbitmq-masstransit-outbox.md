# ADR 0003. RabbitMQ + MassTransit + Outbox

- **Статус:** Accepted
- **Дата:** 2026-04-10

## Контекст

Нужен брокер сообщений для асинхронных сценариев: отправка письма после оформления
заявки, синхронизация поискового индекса. Требуется гарантированная доставка без
потери событий при сбоях.

## Решение

- Брокер — **RabbitMQ** (open-source, прост в изучении).
- Абстракция над брокером — **MassTransit** (публикация, потребители, retry, sagas).
- Публикация событий из БД — через **Transactional Outbox** (таблица outbox +
  доставка MassTransit), чтобы запись заказа и событие были атомарны.
- Потребители **идемпотентны** (дедупликация по `MessageId`/бизнес-ключу).
- Контракты сообщений — отдельный проект `EcoTech.BuildingBlocks.Messaging`.

## Последствия

- (+) Надёжная доставка (at-least-once), повторные попытки, развязка сервисов.
- (+) RabbitMQ легко поднять локально и в k8s.
- (−) Eventual consistency — фронт/админка должны учитывать задержку.
- (−) Kafka была бы уместнее для стриминга больших объёмов, но избыточна здесь.
